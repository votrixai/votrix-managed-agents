Snapshot: 2026-07-15
Runtime kernel: Deep Agents 0.6.12

VMA targets the public resource and SDK shape described by the [Claude Managed Agents overview](https://platform.claude.com/docs/en/managed-agents/overview). It does not claim identical model behavior or managed-infrastructure semantics.

Status meanings:

- **Implemented**: code exists in this repository and the covered behavior has direct tests.
- **Partial**: a route or runtime path exists, but important behavior, durability, security, or exact Claude semantics remain incomplete.
- **Gap**: no production implementation is present.

Passing the official Anthropic Python SDK's strict response validation proves wire compatibility only for the tested requests. It does not promote a partial runtime feature to implemented. See [API route coverage](./managed-agents-api-coverage.md) and [known incompatibilities](./known-incompatibilities.md).

## Public control plane

| Area | Status | Current VMA behavior | Material difference or remaining work |
| --- | --- | --- | --- |
| `/v1` resource paths | Implemented | With `VMA_PUBLIC_GA_ONLY=true`, the public-beta schema exposes API keys, agents, environments (without worker routes), sessions (without threads), files (without presign/complete), Skills, Vaults/native model Credentials, model providers, health, and capabilities. | Memory Stores, deployments, outcomes, user profiles, webhooks, and other experimental repository routes are not public-beta product promises. The route inventory is not a guarantee of compatibility with every future SDK release. |
| Beta and version headers | Implemented | Accepts the native VMA beta header and Claude-compatible Managed Agents, Skills, User Profiles, and Agent Memory beta headers; compatibility requests require `anthropic-version`. | Feature-specific and future preview headers may evolve independently upstream. |
| Native Python SDK | Implemented | `votrix` exposes `AsyncVotrix` for the GA resources and `Votrix` for synchronous API-key, model-provider, Vault, and native model-Credential administration. It includes forward-compatible models, cursor pagination, true streamed downloads, reconnecting SSE, bounded replay-safe retries, request IDs, stable error codes, and provider/BYOK helpers. | `AsyncAnthropic` remains a separately tested compatibility channel, and neither SDK implies behavioral parity with Claude. The first PyPI release is still pending. |
| Model-provider catalog | Implemented | Authenticated native endpoints list/retrieve a deterministic server-approved provider catalog without returning keys, internal credential-slot names, base URLs, model kwargs, or Session-specific credential availability. | Catalog capabilities are operator assertions, not live provider certification. |
| Organization isolation | Implemented | API keys resolve to `CurrentOrganization`; core queries and private object keys are Organization-scoped, and public paths contain no caller-selected Organization identifier. | Postgres RLS is not installed as defense in depth. Organization membership, role inheritance, SSO, and policy evaluation are outside the Votrix core. |
| Organization API-key lifecycle | Implemented | Every supported environment uses database-backed keys with one-time plaintext create/rotate results, hashes at rest, expiration, independent revocation, prefixes, last-used tracking, and `api`, `api_keys:manage`, and `worker` scopes. A trusted CLI bootstraps the first management key without a process-global authentication key. | There are no human users, Organization service accounts, delegated grants, or enterprise key-policy automation. Failed authentication without a resolved Organization is not a tenant-attributed audit fact. |
| Request correlation and errors | Implemented | VMA accepts or generates a request ID, echoes `request-id` and `x-request-id`, includes the ID in errors, and returns stable machine-readable `error.code` values. | Error compatibility is guaranteed for the VMA contract, not every future Anthropic error subtype. |
| Tenant idempotency | Partial | Generic Organization/operation/key/fingerprint records protect Session creation and replay its exact success response. Session event submission has a dedicated transactional idempotency record linked to its work item. | The generic mechanism is not yet wired to every public mutation, and no claim of end-to-end exactly-once provider execution or billing is made. |
| Agent create/retrieve/list/archive | Implemented | Agent resources are mutable pointers to immutable version snapshots. Archived agents cannot start new sessions. | Exact upstream validation can change during beta. |
| Agent update/version guard | Implemented | Updates require the active version, reject stale writes, preserve omitted fields, replace arrays, merge metadata, and avoid no-op versions. | None known for the covered fields; see [agent versioning](./agent-versioning.md). |
| Tool and MCP declaration validation | Implemented | Validates aggregate limits, custom tool names/schemas, MCP server count, unique names, and `mcp_toolset` references. | Validation does not establish a live MCP connection. |
| Multiagent roster pinning | Implemented | Unversioned roster references resolve to immutable referenced versions; roster depth is limited. The strict-BYOK MVP rejects a Session unless the coordinator and every pinned subagent use the same provider. | Execution and event-thread behavior are partial; mixed-provider rosters require a future per-agent credential-binding design. |
| Environment CRUD | Implemented | Stores and validates cloud, self-hosted, and local environment configuration; the optional E2B adapter maps supported egress and lifecycle policy. | E2B resources and preinstalled packages are template-level, package state is not shared across sessions, and custom providers must enforce their own policy. |
| Session CRUD and version pinning | Implemented | Session creation accepts an agent ID, a pinned reference, or CMA-compatible `agent_with_overrides` for model, system, tools, MCP servers, and Skills. It persists and returns the resolved snapshot without changing the Agent version; create/retrieve/list/update/archive/delete responses pass strict SDK tests. Create supports Organization-scoped `Idempotency-Key`, and the native SDK generates one when omitted. Existing callers may omit funding; native callers can choose `byok`, `platform_credits`, or `organization_default`. | Model/provider behavior remains provider-dependent even when the wire contract matches. The native funding selector is a VMA extension. |
| Session state machine | Partial | Persists `idle`, `running`, `rescheduling`, and `terminated`, including retry metadata and `requires_action` as an idle stop reason. Database work/Session leases and generation fencing support the maintained multi-instance worker fleet. | Exactly-once external side effects, complete steering semantics, durable cancellation, and all failure transitions remain incomplete. |
| Session sandbox lifecycle | Partial | With E2B selected, Session creation provisions, seeds, seals revision 0, and pauses exactly one sandbox. Every turn reconnects its private external ID, verifies the fixed Skills/Memory/create identity plus the latest append-only file digest, manifest, and revision, never re-uploads existing inputs, and pauses with full-memory preservation; archive preserves it, delete kills it, and best-effort janitor cleanup defaults to 30 days. | There are no sandbox generations, snapshots, operation leases/heartbeats, durable outbox, or orphan recovery. Database/provider effects are not atomic, scale-to-zero delays cleanup, and the lifecycle is not Anthropic's managed service. |
| Session-local agent changes | Implemented | Create-time overrides use CMA replacement semantics: omitted fields inherit, `system: null` clears the prompt, and empty arrays clear tools, MCP servers, or Skills. Null arrays and `model: null` are rejected. After creation, only tools and MCP servers can be replaced while idle, without creating a new Agent version. Custom Skill `latest` references are pinned to a concrete version in the Session snapshot before sandbox bootstrap. | Create-time model/system/Skill choices are immutable for that Session; changing them requires a new Session, as does changing E2B bootstrap inputs. |
| Event append/list | Implemented | Append-only events have monotonic per-session `seq`; covered input validation and pagination pass strict SDK tests. | The complete Claude event union and every predecessor/processing transition are not implemented. |
| SSE replay and live stream | Partial | Durable events replay from the database. Local mode uses same-process previews; hosted API/worker services preserve transient `event_start` and `event_delta` delivery across instances through PostgreSQL `pg_notify`. | Preview frames are intentionally best-effort and non-replayable; clients must reconcile with durable events. Exact Claude event coverage remains partial. |
| File API | Partial | Authenticated upload/list/retrieve/download/delete, Organization deduplication, upload and Organization stored-byte limits, local EICAR checks, and private S3-compatible source-of-truth storage exist. Bounded direct files generated below `/mnt/session/outputs` are exported as downloadable Session-scoped Files. Mounted JPEG/PNG/GIF/WebP, PDF, and UTF-8 text references are translated from the Managed Agents wire shape into provider-neutral model blocks. | Presign/complete routes are intentionally hidden from public GA. Production malware scanning and retention/content-disarm policy remain incomplete. Binary inline behavior still depends on the selected model's declared multimodal capability; text-only profiles receive a sandbox-path marker. |
| Session resources | Partial | File, GitHub repository, and Memory Store response unions are persisted. E2B resolves supported File and Memory Store inputs at Session creation, uploads them once, and seals immutable content. Idle bound Sessions may append a new read-only File at one direct `/mnt/session/uploads/<filename>` path using the same sandbox and a monotonic manifest revision; existing mounts remain immutable. | E2B Session creation rejects `github_repository` because secure one-time checkout/token handling is not implemented. Skills and Memory Stores cannot be appended, resume never repairs or re-syncs files, and guest write confinement depends on the required hardened E2B template. |
| Skills API | Partial | Validates and versions custom skill archives containing one top-level directory and `SKILL.md`. | Runtime uses Deep Agents skill semantics; Anthropic-provided system skills are not supplied locally. |
| Vault, credential, and Session funding | Partial | Credential unions, redaction, AES-GCM secret persistence, Organization scoping, active-key uniqueness, the 20-Credential limit, immutable structural keys, and cascade revocation exist. A native model-Credential endpoint accepts a public provider ID and maps it to the private credential slot. At Session creation VMA fixes either the first matching Vault Credential or an exact encrypted Organization platform-key row. Rotation stays on the same row; revocation, expiry, or account suspension fails closed without sending the key to E2B. | No complete OAuth enrollment/refresh, KMS policy, monetary credit balance/reservation, or invoice reconciliation exists. Fixed Session funding is a deliberate VMA extension. Keyless `fake` and `ollama` providers use source `none`; mixed-provider multiagent Sessions are deferred. |
| Memory-store API | Partial | Path memories, limits, optimistic preconditions, immutable versions, deletion history, and filtering are implemented; E2B can receive a bounded one-time seed at Session creation. | Read-write sandbox edits persist only in that sandbox and are not written back to managed Memory Store versions or exposed as Claude-compatible bidirectional memory. |
| Multiagent session threads | Partial | Thread resources and pinned roster snapshots can be created and queried. | Deep Agents synchronous delegation is ephemeral and does not reproduce Claude's durable per-agent thread streams. |
| Outcomes | Partial | Outcome request shape, stored metadata, and compatible evaluation-end event shape exist. | No independent production grader loop with Claude-equivalent iteration semantics. |
| Deployments and runs | Partial | CRUD, pause/unpause, manual runs, cron validation, upcoming timestamps, session linkage, and an idempotent due-schedule function exist. | No continuously operated scheduler, distributed fencing, retry service, or delivery SLO. |
| Webhooks | Gap | Signing, verification, timestamp freshness, and envelope helpers exist for tests and integrations. | There is no public-beta webhook product promise: endpoint registration, event fan-out, retries, idempotency, rotation, and failure disabling are absent. |
| User profiles | Partial | Resource lifecycle and relationship metadata exist. | Request attribution/forwarding, enrollment, verification, grants, and hosted access policy are absent. |

## Deep Agents execution plane

| Area | Status | Current VMA behavior | Material difference or remaining work |
| --- | --- | --- | --- |
| Runtime kernel | Implemented | Session turns always compile an immutable VMA agent snapshot into a run-scoped Deep Agents graph, stream it, and persist translated output. Real-graph tests cover execution and checkpoint resume; control-plane tests inject a deterministic executor at the internal adapter boundary. | Deep Agents is a beta library and is not itself a durable multi-tenant service. Exact Claude behavior remains partial. |
| Model-provider resolution | Implemented | Server-owned configuration selects approved adapters, endpoints, routing, defaults, capabilities, and private Vault credential slots; additional approved providers use `VMA_MODEL_PROVIDERS`. The runtime constructs `ChatAnthropic`, `ChatOpenAI`, or `ChatDeepSeek` with the Session-bound Vault key and never resolves model keys from process environment or provider configuration. | Provider capabilities remain heterogeneous. See [model providers](./openai-compatible-providers.md). |
| DeepSeek | Partial | `deepseek-chat` is available through the native LangChain integration. | `deepseek-reasoner` is rejected because the Deep Agents harness requires tool calling; reasoning/event formats also differ from Claude. |
| Checkpoint backend selection | Implemented | LangGraph checkpointers select Postgres in production-style configurations, a separate SQLite database locally, or explicit in-memory mode. | Checkpoints do not replace the VMA event log. Tenant safety still depends on server-owned opaque thread IDs. |
| Checkpoint/interrupt resume | Partial | Pending custom-tool results and approve/reject decisions are grouped by saved interrupt ID and resumed on the same thread; real-graph tests cover cross-turn resume. | Resume across changed deployments requires the original agent revision and compatible graph shape; edit decisions and checkpoint migration remain incomplete. |
| Graph stream translation | Implemented | Parent text, fragmented tool calls, tool results, usage, and HITL interrupts are translated into durable VMA events; previews and final events share exact event IDs. | Full Claude event/span union and child-agent thread routing remain partial. |
| Conversation compaction | Partial | Deep Agents supplies model-aware summarization and compact checkpoint message state. | Trigger thresholds and summary wording are not Claude's managed compaction implementation. |
| Built-in filesystem tools | Partial | Claude names map to Deep Agents `ls`, `read_file`, `write_file`, `edit_file`, `glob`, `grep`, and optional `execute`; disabled tools are filtered from model requests. | Tool schemas, result text, path behavior, and error payloads are not byte-for-byte Claude equivalents. |
| Web tools | Partial | `web_fetch` enforces public HTTP(S), redirect revalidation, and response limits; `web_search` can call an operator-provided JSON endpoint. | Search ranking, citations, availability, and policy do not match Anthropic's hosted tools. |
| Permission policies | Partial | `always_ask` tool configs map to LangGraph human-in-the-loop interrupts for supported tools. | Tool middleware is not a security boundary; shell/file policy must be enforced by the sandbox. Edit/respond decision parity and all MCP approval cases need continued contract work. |
| Custom tools | Partial | Custom schemas become client-owned Deep Agents tools, pause with a respond-only interrupt, persist their public event IDs, and resume from matching application results. | Idempotency and exact Claude behavior are not complete for every concurrent, cancellation, or retry path. |
| MCP runtime | Partial | Runtime matches vault credentials by normalized MCP URL and can construct remote MCP tools with static authorization headers. Missing credentials emit non-terminal session errors. | MCP currently runs in the control plane, so `allow_mcp_servers` does not map to E2B egress; OAuth refresh, discovery, revocation, reconnect policy, capability drift, and complete approval events are also missing. |
| Custom skills at runtime | Partial | Versioned archives remain in S3-compatible storage, are selected and traversal/symlink checked, then are materialized once below `/skills/custom` when an E2B Session is created. The sealed Skill identity is verified on every turn. | Skills cannot change within an E2B Session; a change requires a new Session. Deep Agents does not guarantee Claude's prompt, cache behavior, or security policy. |
| Anthropic system skills | Gap | References can be accepted as compatibility data. | VMA does not have Anthropic's private skill packages and skips them during local runtime materialization. |
| Memory at runtime | Partial | A bounded Memory Store seed is materialized once at each mount with an `AGENTS.md` source. E2B seals read-only memory; read-write memory remains mutable and persists in the same sandbox across turns. | Runtime edits are not written back to managed Memory Store versions; custom execute-capable backends must enforce access themselves, and no semantic index exists. |
| Synchronous subagents | Partial | Pinned VMA roster entries map to Deep Agents declarative `SubAgent` specifications and the `task` tool. | Calls are ephemeral and return one result to the coordinator; they do not create equivalent durable Claude session threads. |
| General-purpose subagent | Partial | Deep Agents may add its built-in general-purpose subagent whenever `task` is exposed. | Harness profiles are process-global, so exact per-agent roster exclusion needs an adapter change or carefully fixed startup profile. |
| Background subagents | Gap | Deep Agents offers `AsyncSubAgent` as an upstream capability. | It speaks LangGraph Agent Protocol, not the VMA/Claude session-thread API, and is not exposed as compatible background orchestration. |
| Safe default backend | Implemented | Without a selected remote provider or factory, `StateBackend` supplies checkpointed file state and does not expose shell execution. | It is not a cloud sandbox and does not enforce environment network/package policy. |
| E2B remote sandbox | Partial | The `sandbox-e2b` extra pins `langchain-e2b==0.0.5` and `e2b==2.31.0`; `VMA_SANDBOX_PROVIDER=e2b` gives Deep Agents the one Session-bound `AsyncE2BSandbox`. A named operator-owned hardened template is mandatory; VMA checks its default guest is non-root, cannot use passwordless sudo, and cannot modify the trusted system interpreter roots used for isolated root bootstrap. Secure access is enabled, public traffic and provider auto-resume are disabled, full-memory pause preserves `/workspace` and read-write memory, append-only Session uploads advance a verified seal, bounded outputs are exported, and limited egress uses E2B `allow_out`. | No lifecycle leases/outbox/orphan recovery or managed-file sync exists. E2B is hosted unless deployed with BYOC; limited mode adds no separate deny-all rule, resources/packages are template-level and trusted from the operator-declared profile rather than independently attested, read-write memory edits are not written back to the Memory Store, and E2B supplies additional untrusted Session-local writable paths outside the durable `/workspace` and memory contract. See [sandbox runtime](./sandbox-runtime.md). |
| Custom remote sandbox | Partial | `VMA_SANDBOX_FACTORY` remains the provider integration boundary. | The operator is responsible for isolation, policy enforcement, lifecycle, retention, and compatibility. |
| Unsafe local shell | Implemented | Explicit local-only mode uses `LocalShellBackend` with an Organization/Session-derived root and minimal environment inheritance. | It executes in the control-plane host and must never be used for untrusted tenants. |
| Run timeout and graph steps | Partial | Settings cap graph recursion and wall-clock runtime; Organization daily model-token quota is preflighted and actual usage is recorded postflight. | Per-turn/context, tool-call, subprocess, network, provider-request, sandbox-compute, and monetary spend budgets are not enforced end to end. |
| Cancellation and retries | Partial | Session retry metadata, capped work attempts, database lease/generation fencing, and Deep Agents dangling-tool-call repair cover some paths. | Provider calls, MCP requests, and remote commands still need cooperative cancellation and operation-specific idempotency; database fencing does not make remote side effects exactly-once. |

| Relational persistence | Implemented | SQLAlchemy and Alembic support SQLite locally and Postgres for deployment. | Production backup, RLS, restore testing, and data lifecycle are operator responsibilities. |
| Object persistence | Partial | A private S3-compatible bucket supplies uploaded files and Skill archives for Session bootstrap and append, while bounded generated outputs are snapshotted as immutable Session-scoped Files. VMA authenticates downloads; no public bucket URL is required. The sealed sandbox copies remain independent. | There is no continuous managed-file sync; arbitrary `/workspace` edits and read-write memory changes remain only in E2B. Retention, malware quarantine, regional replication, and Organization-managed keys are not productized. |
| Durable work records | Implemented | Postgres work items support queueing, unique lease IDs and generations, ack, execution heartbeats, capped attempts, retry gates, stop, expired-lease recovery, stale-worker terminal-write fencing, and idempotent active-work quota release. Hosted execution runs in a private, manually scaled multi-instance worker service with shared PostgreSQL checkpoints. | Provider and sandbox side effects are not exactly-once. Managed push dispatch, queue-depth autoscaling, and a separate dead-letter resource remain deferred. |
| Live-preview broker | Implemented | `process_local` remains the local default; hosted services use Organization/Session-scoped PostgreSQL `pg_notify` delivery between workers and API instances with local loopback suppression and bounded coalescing. | Delivery is best-effort and single-database scoped; dropped previews are reconciled by durable events rather than replayed. Hosted API processes each consume one dedicated session-mode `LISTEN` connection. |
| Scheduler | Partial | An importable, idempotent due-schedule tick exists. | No always-on scheduler service or production retry SLO is included. |
| Authentication | Implemented | Local, development, staging, and production fail closed through database-backed Organization API keys. Scopes are enforced before resource access and request quota consumption. | Hosted user sessions, Organization service accounts, OAuth/OIDC, and human identity policy need a private layer. |
| RBAC and SSO | Gap | Not part of the Organization-scoped Votrix core. | Required for a managed enterprise service. |
| Tenant quotas and raw usage | Implemented | Atomic per-Organization counters enforce requests/minute, active work, daily model tokens, and stored bytes. Provider-reported actual token usage is appended idempotently with provider/model attribution, and quota denials expose stable codes and reset metadata. A turn admitted below the token limit may cross it; all reported usage is retained and later turns are blocked until the UTC-day reset. | This is beta quota/metering for BYOK cost analysis, not priced billing. Sandbox count/compute/egress, tool/MCP calls, event retention, and monetary spend limits remain absent. |
| Audit ledger | Implemented | Organization-attributed authorization decisions, request completion, quota actions, and runtime governance facts are appended to an ORM- and database-trigger-protected ledger with request IDs and actor/resource metadata. | Enterprise export, automated retention, legal hold, external tamper anchoring, complete secret-read coverage, and administrator/support access history remain absent. |
| Billing and payments | Gap | Trusted operators may provision hard-limited provider sub-keys per Organization for trials, and VMA retains raw Organization/Session usage facts. | `platform_credits` is a funding selector, not a prepaid ledger. | Compliance | Gap | No compliance certification is claimed. | Isolation, retention, deletion verification, incident response, and regional controls require deployment-specific work. |

## Compatibility rule

When a public response can match Claude but the execution semantics cannot, VMA should preserve the compatible wire shape, expose the limitation in session events or operator diagnostics, and keep the row **Partial**. It must not silently claim managed behavior that the configured model, broker, secret provider, or sandbox cannot provide.
