Votrix Managed Agents is a proprietary service for running long-lived,
versioned agents, built with FastAPI, Deep Agents, LangGraph, E2B, and
SQLAlchemy.

<Callout title="Development authentication boundary" type="warn">

The active implementation requires `x-organization-id` but does not yet
authenticate that tenant selection. Do not expose it directly to untrusted
clients. Read [implementation status](./rewrite-status.md) for the remaining
production gaps.

</Callout>

## Current capabilities

- immutable Agent versions and Session version pinning;
- E2B Environment image recipes;
- one persistent E2B sandbox per Session;
- append-only Session events and resumable SSE;
- Deep Agents filesystem tools, Skill loading, and human-in-the-loop tool
  decisions;
- private S3-compatible File and Skill storage;
- SQLite or PostgreSQL resource state and separate LangGraph checkpoints;
- inline turns or OIDC-authenticated Cloud Tasks push dispatch.

Implemented resource routes trust `x-organization-id` and do not validate
`x-api-key`. The Organization and model placeholders do not yet use that
dependency. The service must not be exposed to untrusted clients.

## Run the active app

Requirements:

- Python 3.12 or newer
- [`uv`](https://docs.astral.sh/uv/)

From the repository root:

```bash
cp .env.example .env
uv sync
uv run alembic upgrade head
uv run uvicorn app.main:app --reload
```

The OpenAPI document is available at
`http://127.0.0.1:8000/openapi.json`.

The first active Alembic revision starts a new lineage. Use a fresh database;
`alembic upgrade head` does not upgrade databases stamped with the superseded
lineage. Moving that data requires a separate migration based on Git history.

List Agents with the current development tenant header:

```bash
curl http://127.0.0.1:8000/v1/agents \
  --header "x-organization-id: org_local"
```

The database defaults to a local SQLite file. A full Session run additionally
needs an E2B key and one model-provider key:

```dotenv
E2B_API_KEY=...
ANTHROPIC_API_KEY=...
```

Use `GEMINI_API_KEY`, `DEEPSEEK_API_KEY`, or `OPENAI_API_KEY` for a model from
those providers. Files, Skills, attached inputs, and output collection need
private S3-compatible storage:

```dotenv
S3_ENDPOINT_URL=https://...
S3_ACCESS_KEY_ID=...
S3_SECRET_ACCESS_KEY=...
S3_BUCKET_NAME=...
```

## System shape

```text
HTTP client
  |
  v
FastAPI router -> service -> tenant-scoped SQLAlchemy query -> SQLite/Postgres
                    |
                    +-> E2B sandbox and image
                    +-> private S3-compatible storage
                    +-> inline turn or Cloud Tasks callback
                                      |
                                      v
                              Deep Agents + LangGraph
                                |       |       |
                                v       v       v
                              model   tools   checkpoint

SSE reader <---- polls committed session_events
```

Routers own HTTP, services own use-case rules and commits, queries own
persistence, and the runtime translates between Deep Agents state and public
events. The sandbox is the execution boundary; the relational event log is the
client-facing source of truth.

## Documentation authority

The navigation contains only documentation reviewed against the active app.
The API reference is generated from `app.server.create_app`; a snapshot test
fails when its checked-in OpenAPI schema no longer matches the application.

## Tests

```bash
uv run pytest
```

The default suite is isolated and runs against in-memory SQLite. Real E2B,
storage, model, and Cloud Tasks checks live under `tests_live/` and must be run
deliberately.
