Votrix Managed Agents (VMA) is an open-source, self-hosted, multi-tenant control
plane for long-running agents. It targets the public resource, lifecycle, and
SDK shape of Claude Managed Agents while running agents with Deep Agents and
LangGraph.

<Callout title="Project maturity" type="warn">

VMA is an early `0.1.0` public-beta foundation. It is not an Anthropic service
or a drop-in behavioral replacement. When `VMA_PUBLIC_GA_ONLY=true`, the
published API is intentionally limited to tenant-isolated resources ready for
the controlled beta; the repository also contains deferred routes.

Start with the [compatibility matrix](./compatibility-matrix.md) and
[known incompatibilities](./known-incompatibilities.md) before using it for
real workloads. The checked-in Cloud Run shape remains single-instance and is
not a high-availability or enterprise claim.

</Callout>

## Run locally

VMA requires Python 3.12 or newer and
[`uv`](https://docs.astral.sh/uv/). From the repository root:

```bash
cp .env.example .env
uv sync
uv run alembic upgrade head
uv run python -m scripts.bootstrap_api_key \
  --workspace-id wrkspc_local \
  --workspace-slug local \
  --workspace-name "Local development"
./run.sh
```

Check the service:

```bash
curl http://127.0.0.1:8080/health
curl http://127.0.0.1:8080/health/db
```

Local, development, staging, and production all fail closed through
database-backed workspace keys with scopes, expiration, independent
rotation/revocation, and one-time plaintext secrets. The bootstrap command
creates the first workspace and administrator key; there is no anonymous or
process-global authentication path. Supply its returned secret to local and
development clients as `VOTRIX_API_KEY`; the service still resolves it from the
database. Hosted environments also require durable Postgres and private object
storage.

For the local SDK or pilot script, save the one-time plaintext in the client
environment as `VOTRIX_API_KEY`. In the API Playground, enter the same value in
the `x-api-key` authentication field. Raw HTTP clients may use either standard
authentication header:

```bash
export VOTRIX_API_KEY='<secret from bootstrap output>'
curl http://127.0.0.1:8080/v1/capabilities \
  --header "x-api-key: $VOTRIX_API_KEY" \
  --header "votrix-managed-agents-beta: votrix-managed-agents-2026-04-01"
```

An `Authorization: Bearer $VOTRIX_API_KEY` header is equivalent.

The public-beta platform enforces per-workspace request, active-work, daily
model-token, and stored-byte limits. It records append-only raw audit and usage
facts and exposes request IDs and stable error codes. The release is BYOK/free:
usage supports quota enforcement and cost analysis, not pricing, balances,
credits, payments, refunds, Stripe, or invoices.

## System shape

```text
AsyncVotrix native SDK / AsyncAnthropic compatibility / HTTP client
                              |
                              v
FastAPI compatibility and control plane
  |         |             |
  |         |             +-- private S3-compatible object storage
  |         +---------------- Postgres resources, events, work, quotas, ledgers
  +-------------------------- durable session and revision lookup
            |
            v
Deep Agents + LangGraph checkpoints
  |                 |                 |
  v                 v                 v
model provider   remote MCP       sandbox backend
```

The control plane owns public IDs, workspace isolation, immutable revisions,
session state, durable events, and compatibility translation. The sandbox—not
the model or middleware—is the security boundary for tenant code.
