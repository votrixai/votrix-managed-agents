The API Reference is the source of truth for VMA's public HTTP contract. It
covers creating Agents, starting Sessions, sending work, following progress,
and managing the resources an Agent can use.

## Base URL

```text
https://api.vma.votrixai.com
```

## Authentication

Send your VMA API key with every request:

```http
x-api-key: YOUR_API_KEY
```

The key identifies the Organization the request can access. Keep it on a
trusted server and do not expose it in browser code or public repositories.

## Request conventions

- Most request and response bodies use JSON.
- File and Skill uploads use `multipart/form-data` where shown.
- Resource IDs have readable prefixes such as `agent_`, `sess_`, and `file_`.
- List endpoints use cursors. Return the supplied `last_id` as `after_id` to
  continue forward, or use an endpoint's opaque `next_page` value when shown.
- A resource that does not exist or is outside the key's Organization returns
  the same `404 not_found` response.

## Events and errors

Session events are ordered by `seq`. You can list them over HTTP or follow them
as server-sent events and resume from the last sequence you processed.

Most API errors use an `error` object with a machine-readable `type` and a
human-readable `message`. See [Errors](/docs/errors) for the full behavior.
